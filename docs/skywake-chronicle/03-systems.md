# 03. 系统设计（可实现版）

## 1. 队伍与角色

- 出征队伍固定 3 人。
- 每名角色包含：
  - Aspects：`High Concept`、`Trouble`、`Background`
  - Skills：6-8 个核心技能中的分配
  - Stunts：3-5 个特性
  - Stress：体力压力条 + 精神压力条（或合并为一个）
  - Consequences：轻/中/重后果槽
- 成长驱动采用分阶段混合：
  - 前期（新手到中前期）：等级成长主驱动，保证线性可感知提升
  - 中期：装备构筑主驱动，形成刷取与制作目标
  - 后期：战术熟练与规则优化主驱动，提升上限与稳定性

## 2. 战斗模型（自动）

- 回合制（事件驱动），每回合：
  1. 评估战术规则
  2. 选择动作（Overcome/Create Advantage/Attack/Defend）
  3. 结算结果并记录日志
- 站位：前排/后排限制可攻击目标。
- 结果形态：
  - 成功
  - 代价成功
  - 失败
  - 灾难失败（可选）
- 可视化粒度：
  - 默认展示日志流
  - 支持“关键回合简化回放”（开战、转折、撤退、胜负结算）

## 3. 探索模型

- 迷宫 = 多层
- 每层 = 节点图（战斗/事件/机关/营地/宝箱）
- 出征时锁定 run seed，保证可复现。
- 每层耗时由“基础耗时 + 事件耗时”构成。
- 探索阻断机制占比（内容投放目标）：
  - 门锁：30%
  - 环境阻断：50%
  - 时间窗：20%

动态时长估算（用于 UI 的“预计耗时”）：

- `eta_min = floor_base_min * target_floor + node_event_min + detour_min`
- `node_event_min = sum(node_weight * event_cost_min)`
- `detour_min = max(0, blocked_node_count * 0.5)`
- 展示区间：`eta_min ~ eta_min * 1.35`

约束：

- 单次出征最短 6 分钟。
- 单次出征最长 90 分钟（超过则提示拆分目标层）。

## 4. 撤退与中断

- 战斗中逃亡：即时触发。
- 探索中断：节点结算后触发。
- 撤退条件来源：
  - 角色压力阈值
  - 队伍资源阈值
  - 指定敌人/场景标签
  - 任务条件不满足

撤退判定顺序（固定）：

1. 强制条件（任务不满足、关键路径阻断）。
2. 生存条件（任一角色压力/后果超阈值）。
3. 资源条件（药剂、战斗资源不足）。
4. 战术条件（玩家自定义撤退规则）。

## 5. 经济与制作

- 货币：金币
- 资产：装备、消耗品、任务物、材料
- 制作：
  - 基础：升阶、重铸
  - 中期：双装备融合（继承 1 条标签 + 1 条词条）

重惩罚结算规则（MVP 量化）：

- `completed`：保留 100% 金币、100% 材料、100% 任务推进。
- `retreated`：保留 45% 金币、60% 材料、任务推进仅保留已达成节点。
- `failed`：保留 20% 金币、30% 材料、任务推进回退到上一个稳定节点。

失败后追加状态：

- 团队随机 1 名角色获得“轻度后果”。
- 修整费用按角色等级线性增长（用于控制连续无脑冲层）。

## 6. 任务系统

- 主线：章节推进，解锁地图与系统
- 支线：素材、挑战、时段任务
- 任务条件支持：
  - 进入特定节点
  - 使用特定道具/标签
  - 在指定时间窗完成

## 7. 反作弊与离线推进

- 采用“出征时预模拟 + 时间切片解锁日志”。
- 设备时间变更触发校验标记。
- 可选服务器校时（商业化版本建议开启）。

## 8. 已拍板决策（2026-02-25）

1. 角色成长主驱动：分阶段混合（前期等级 -> 中期装备 -> 后期战术）。
2. 战斗可视化粒度：日志 + 关键回合简化回放。
3. 探索阻断机制占比：门锁 30% / 环境 50% / 时间窗 20%。

## 9. 系统验收口径（MVP）

- 可复现性：
  - 同 `seed + dungeon_id + party_snapshot` 重跑，事件序列一致。
- 可解释性：
  - 每次撤退/失败必须产生至少 1 条核心 `reason_tag`。
- 可调参性：
  - 修改战术规则后，下一次 run 能在日志中看到规则命中差异。
