# 01. 产品总览（GDD）

## 1. 产品定位

- 名称（暂定）：`苍穹航痕 Skywake Chronicle`
- 类型：自动探索 + 日志推理 + 长线养成 RPG
- 目标平台：iOS / Android
- 叙事风格：日系群像冒险，章节式推进
- 目标用户策略：
  - 中度玩家：通过“战术风格模板（好斗/谨慎/均衡）+ 自动调参”快速上手
  - 硬核玩家：开放规则级编辑（条件/动作/优先级）进行手动调参

一句话：玩家不是“手操战斗”，而是“配置小队规则 -> 派遣 -> 读日志 -> 调参复跑”。

## 2. 核心体验支柱

1. 可解释：每次失败都能在日志中找到原因与线索。
2. 可迭代：战术规则和装备构建有明确反馈闭环。
3. 可成长：队伍、城镇、航线、制作系统形成长期目标。

## 3. 核心循环

1. 城镇准备：
   - 组队（3人）
   - 装备/技能/战术配置
   - 接任务
2. 选择探索：
   - 迷宫/目标层/目标节点
   - 动态预计耗时显示（随关卡阶段、节点事件密度、队伍状态变化）
3. 自动执行：
   - 跑图、战斗、事件、撤退
   - 持续产生日志
4. 结算回城：
   - 奖励、进度、失败原因标签
   - 再配置再出发

## 4. 元循环（Meta Loop）

- 周期目标：完成章节主线、解锁新城镇和新迷宫。
- 中期目标：构筑稳定战术模板（例如高生存、速通、素材队）。
- 长期目标：稀有制作、终局迷宫、分支结局。

## 5. 设计原则

1. 系统优先于文本：先保证“结果可复盘”，再写剧情包装。
2. 策略优先于手速：玩家投入应在“判断”和“配置”。
3. 失败必须有价值：日志给出下一步行动方向。

## 6. 成功指标（MVP阶段）

- D1：> 35%
- D7：> 12%
- 平均单次会话：> 8 分钟
- 关键指标：
  - `retreat_reason` 分布可解释
  - > 60% 玩家在失败后 10 分钟内二次出征

## 7. 已拍板决策（2026-02-25）

1. 目标用户：采用“中核 + 硬核双轨”。
   - 中核走战术模板自动调参。
   - 硬核走规则编辑手动调参。
2. 探索时长：采用动态时长，不固定单一档位。
3. 失败惩罚：采用重惩罚（高风险高回报）。

## 8. MVP 范围边界（In / Out）

In Scope（MVP 必做）：

- 3人队自动探索全链路（准备 -> 出征 -> 日志 -> 结算）。
- 战术模板（中度）+ 规则编辑（硬核）双轨入口。
- 重惩罚结算规则（可解释且可预期）。
- 1 城镇 + 2 迷宫 + 1 章主线 + 支线任务。

Out of Scope（MVP 不做）：

- 实时 PVP/PVE 联机。
- 云存档和跨设备实时同步。
- 公会/排行榜赛季化系统。

## 9. 非功能目标（MVP）

- 启动性能：
  - 冷启动 <= 4 秒（中端机目标）。
- 运行性能：
  - 战斗/日志页面操作帧率目标 >= 55 FPS。
- 稳定性：
  - 崩溃率 < 1%（与排期风险阈值一致）。
- 可观测性：
  - 所有 run 必须有 `run_id` 与完整结算事件。

## 10. 重惩罚设计护栏

为了避免“重惩罚变成劝退”，MVP 采用以下护栏：

- 每次失败必须返回“明确可行动线索”（道具/战术/时间窗之一）。
- 连续失败保护：
  - 同一任务连续失败 3 次后，提供一次免费战术模板建议。
- 资源底线：
  - 失败不会让核心进度（章节解锁状态）倒退。
