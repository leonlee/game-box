# 07. MVP 路线图（8 周）

目标：8 周内交付“可跑、可解释、可迭代”的首个可玩版本。

## 1. 里程碑总览

1. W1-W2：规则核心与数据骨架
2. W3-W4：自动探索闭环 + 日志系统
3. W5-W6：战术编辑器 + 内容首包
4. W7-W8：平衡、留存、商店化最小闭环

## 2. 周计划

### W1

- 冻结 Schema v0.1（角色/技能/迷宫/任务/run_events）
- 实现 deterministic seed 与 run 重放框架
- 产出：可跑的 headless 模拟器（CLI）

### W2

- 完成战斗动作执行器（四动作）
- 完成基础伤害/压力/后果结算
- 产出：最小战斗日志可回放

### W3

- 完成 dungeon node 流程（战斗/事件/门/营地）
- 完成撤退与中断规则
- 产出：1 个迷宫全流程可跑通

### W4

- 完成日志系统双视图（叙事/调试）
- 接入 reason tags 与失败统计
- 产出：可定位失败原因的复盘页

### W5

- 实装战术编辑器 v0（条件/动作卡片）
- 实现规则排序、启用禁用、模板导入
- 产出：3 套预设战术可切换

### W6

- 内容首包：1 城镇 + 2 迷宫 + 6 角色模板
- 完成任务链（主线 1 章 + 支线 6 条）
- 产出：首小时可玩内容

### W7

- 经济与制作最小闭环（掉落/商店/重铸）
- 平衡首轮（撤退率、失败率、产出速率）
- 产出：核心数值 v0.9

### W8

- 新手引导、通知、设置、存档迁移
- QA 回归与崩溃收敛
- 产出：MVP 提测包

## 3. 验收标准（Go/No-Go）

- 功能：
  - 从组队到回城全链路无阻塞
  - 失败场景均有 reason tags
  - 日志可重放且顺序稳定
- 体验：
  - 新用户 15 分钟内完成首次复跑
  - 至少 1 个“读日志 -> 改配置 -> 成功”的正反馈案例
- 技术：
  - 同一 seed 复跑结果一致
  - run_events 落盘完整，崩溃可恢复

阶段退出门槛（按周）：

- W2 退出门槛：
  - CLI 模拟器可跑完一场完整战斗并导出事件序列。
- W4 退出门槛：
  - 失败 run 至少 95% 能归因到核心 `reason_tags`。
- W6 退出门槛：
  - 首小时内容可玩通路（新号从建队到完成首个主线节点）。
- W8 退出门槛：
  - 崩溃率 <= 1%，核心阻塞问题 <= 3。

## 4. 风险与缓解

1. 战术规则爆炸导致不可控：
   - 缓解：MVP 只开放 12 条条件 + 14 条动作。
2. 日志文本成本过高：
   - 缓解：模板化 + loc_key 参数化，不写一次性散文。
3. 平衡调优慢：
   - 缓解：优先做埋点与可视化统计，再做细调。

依赖关系（关键）：

- W1/W2 未完成，不进入 W3 的迷宫全流程联调。
- W4 的日志看板未就绪，不进入 W7 的平衡迭代。
- W5 的战术编辑器未稳定，不进入 W6 的大规模内容灌入。

## 5. 人力建议（最小编制）

- 客户端 2（系统 + UI）
- 玩法/后端 1（模拟器 + 数据）
- 策划 1（系统 + 内容）
- QA 1（可兼职）

## 6. 已拍板决策（2026-02-25）

1. 8 周范围锁定，不新增系统级需求（`1A`）。
2. 每周演示采用“产品 + 技术双签”验收（`2B`）。
3. 风险预案触发阈值（`3B`）：
  - 崩溃率 > 1%，或
  - 核心流程阻塞问题 > 3 个。

## 7. 每周演示固定产物

- 产品视角：
  - 10 分钟可跑演示（录屏或现场）
  - 本周风险与下周变更请求清单
- 技术视角：
  - 本周 schema/接口变更说明
  - 本周新增埋点与异常分布
